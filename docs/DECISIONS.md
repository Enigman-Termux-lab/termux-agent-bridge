# 🏛️ Архитектурные решения: Termux Agent Gateway

Документ фиксирует ключевые архитектурные и технические решения, принятые в процессе создания и трансформации **Termux Agent Gateway**.

---

## 1. Концепция шлюза и переход к универсальности
* **Проблема:** Первоначальный прототип был жестко завязан на Gemini Spark (`gemini-spark-mcp-bridge`), имел захардкоженные URL и не имел разграничения прав доступа.
* **Решение:** Проект преобразован в универсальный шлюз `termux-agent-gateway` по открытому стандарту MCP (Model Context Protocol 2024–2026), поддерживающий всех современных агентов: OpenAI Codex, Claude Code, Google Antigravity, Gemini Spark, Cursor, Windsurf.

---

## 2. Матрица 4 динамических профилей безопасности (Security Profiles)
* **Решение:** Вместо статического набора функций реализована фабрика MCP-сервера, регистрирующая строго разрешенный пул инструментов в зависимости от выбранного режима:
  1. `MONITOR` (риск 0/5): инструменты чтения (`system_status`, `battery_info`, `tail_log`). Запуск bash и запись файлов физически отсутствуют в схеме MCP.
  2. `WORKSPACE` (риск 2/5): песочница в `~/workspace` (`workspace_bash`, `file_read`, `file_write`). Запрещен выход через `..` или симлинки, блокированы пакетные менеджеры и доступ к системным каталогам Android.
  3. `INTERACTIVE` (риск 1.5/5, режим по умолчанию): безопасные команды (ls, cat, git status) выполняются сразу; деструктивные операции (`rm`, `mv`, `pkg`, `kill`, `chmod`, `curl`, `wget`, `> /`, `git push --force`) вызывают push-уведомление в Android с кнопками «Разрешить» и «Заблокировать» (таймаут 45 секунд).
  4. `GODMODE` (риск 5/5): полный доступ к Termux bash, запуск локального автономного агента Antigravity CLI (`agy`) и Android API.

---

## 3. Транспорт и сетевая безопасность
* **Транспорт:** Выбран **Streamable HTTP** (POST/GET) + SSE алиасы. Это устранило проблему с HTTP 405 Method Not Allowed при подключении облачных клиентов (Spark / Codex) и обеспечило совместимость со стандартом MCP 2024-11-05+.
* **DNS Rebinding & CORS:** Отключена встроенная защита от DNS-rebinding (`enable_dns_rebinding_protection=False`), что критически необходимо для работы через публичные динамические или статические домены Ngrok (`*.ngrok-free.dev`). Настроен глобальный CORSMiddleware.
* **Capability URL:** Аутентификация построена на длинных криптографических секретных путях (`/<SECRET_PATH>/sse`), что избавляет от сложностей с OAuth/Bearer для клиентов с `Authentication: None`. Сохранен алиас `OLD_SECRET_PATH` для бесшовной миграции клиентов.

---

## 4. Android Push Approval (Интерактивное подтверждение)
* **Реализация:** Модуль `approval_daemon.py` использует `termux-notification` из пакета Termux:API. При обнаружении опасного паттерна в команде генерируется уникальный `request_id`, отправляется уведомление с кнопками «Разрешить» (`--button1-action "touch /tmp/.../approve_$id"`) и «Заблокировать» (`--button2-action "touch /tmp/.../deny_$id"`), а также подается вибросигнал `termux-vibrate`.
* При отсутствии отклика в течение 45 секунд или нажатии «Заблокировать» запрос прерывается с ясным уведомлением агента.

---

## 5. Zero-to-Hero Онбординг (`gateway.sh`)
* Создан интерактивный шелл-скрипт `gateway.sh`, проверяющий наличие системных пакетов (`python`, `termux-api`, `ngrok`, Python SDK), настраивающий токен ngrok, генерирующий секрет и сохраняющий конфигурацию в `~/.termux_agent_gateway.env`.
* Скрипт поддерживает команды: `run`, `start`, `stop`, `restart`, `status`, `config`, `copy`, автоматически копирует готовый адрес в системный буфер Android (`termux-clipboard-set`) и запускает ngrok через `termux-chroot` для обхода Android DNS багов.
